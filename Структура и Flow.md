Ниже представлены две подробные схемы для нашего проекта LedgerFlow:

## 🔄 1. Схема флоу приложения (Архитектура LedgerFlow)
Схема показывает, как запрос проходит через систему и как данные асинхронно попадают в Kafka брокер через 
паттерн Transactional Outbox.

```
 Клиент (Тест)
     │
     │  1. POST /orders { Amount: 500 }
     ▼
┌────────────────────────────────────────────────────────────────────────┐
│ LedgerFlow.Api (Рантайм приложения в памяти TestServer)                │
│                                                                        │
│   ┌──────────────────┐                                                 │
│   │  Minimal API     │                                                 │
│   │  (Program.cs)    │                                                 │
│   └────────┬─────────┘                                                 │
│            │                                                           │
│            │ 2. Открывает транзакцию EF Core                           │
│            ▼                                                           │
│   ┌───────────────────────────────────────────────────────────────┐    │
│   │ OrderDbContext (Атомарная финтех-запись)                      │    │
│   │                                                               │    │
│   │  [Таблица Orders]        ◄── Добавляет запись Заказа          │    │
│   │  [Таблица OutboxMessages] ◄── Добавляет событие OrderCreated  │    │
│   └────────────────────────┬──────────────────────────────────────┘    │
│                            │                                           │
│                            │ 3. COMMIT (Данные железно в БД)           │
│                            ▼                                           │
│                 ┌────────────────────┐                                 │
│                 │ Постгрес (Docker)  │                                 │
│                 └──────────┬─────────┘                                 │
│                            │                                           │
│                            │ 4. Периодический опрос (раз в 2 сек)      │
│                            ▼                                           │
│   ┌───────────────────────────────────────────────────────────────┐    │
│   │ OutboxPublisherWorker (BackgroundService)                     │    │
│   │                                                               │    │
│   │  - Выбирает top(10) сообщений, где ProcessedAt == null        │    │
│   └────────────────────────┬──────────────────────────────────────┘    │
│                            │                                           │
│                            │ 5. Отправляет сообщение                   │
│                            ▼                                           │
│   ┌───────────────────────────────────────────────────────────────┐    │

└────────────────────────────┼───────────────────────────────────────────┘

                    ┌─────────────────┐

                    └─────────────────┘
```

## 📁 2. Схема структуры решения (Solution Tree)

```
📁 LedgerFlow.System (Коллективный Solution)
│
├── 📁 src/
│   └── 📁 LedgerFlow.Api/
│       │
│       ├── 📁 BackgroundServices/
│       │   └── 📄 OutboxPublisherWorker.cs  # Фоновый воркер опроса Outbox таблицы
│       │
│       ├── 📁 Data/
│       │   └── 📄 OrderDbContext.cs         # Контекст EF Core (Orders, Outbox)
│       │
│       ├── 📁 Messaging/
│       │   └── 📄 IMessageBroker.cs         # Интерфейс брокера и фейк-заглушка
│       │
│       ├── 📁 Models/
│       │   └── 📄 Models.cs                 # Доменные сущности (Order, Outbox) и DTO
│       │
│       ├── 📄 appsettings.json              # Базовые настройки (строка подключения)
│       ├── 📄 appsettings.Development.json  # Локальные настройки разработки
│       ├── 📄 LedgerFlow.Api.csproj         # Файл настроек проекта API (.NET 9)
│       └── 📄 Program.cs                    # Точка входа, DI, ручки GET и POST
│
└── 📁 tests/
    └── 📁 LedgerFlow.IntegrationTests/
        │
        ├── 📁 Infrastructure/
        │   └── 📄 CustomWebApplicationFactory.cs # НАШ БУДУЩИЙ ШАБЛОН (Блок 1)
        │
        ├── 📁 Tests/
        │   ├── 📄 OrderApiTests.cs          # Сюда напишем первый тест (Блок 1)
        │   └── 📄 OutboxTests.cs             # Будущие тесты брокера (Блок 3)
        │
        ├── 📄 LedgerFlow.IntegrationTests.csproj # Настройки тестового проекта (xUnit v3)
        └── 📄 Usings.cs                     # Глобальные using-директивы для тестов
```

## 🛠 Что делать на вашей стороне прямо сейчас:

   1. Создайте пустой Solution с именем LedgerFlow.System.
   2. Создайте Web API проект (в папке src) и проект тестов xUnit (в папке tests).
   3. Разложите код, который мы написали в предыдущих шагах, по соответствующим файлам из схемы выше (Models.cs, OrderDbContext.cs, IMessageBroker.cs, OutboxPublisherWorker.cs, Program.cs).
   4. Убедитесь, что проект LedgerFlow.Api успешно собирается (Build Success).
